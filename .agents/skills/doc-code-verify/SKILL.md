# 문서-코드 정합성 검증

## 1. 검증 실행

- `verifier` 에이전트를 `mode=code`로 실행한다. 프롬프트에는 feature ID, PRD 버전, 통합 브랜치, 산출물 경로(`artifacts/work/F-##/VERIFY.md`)만 준다. 구현 의도나 자기평가를 넣지 않는다.
- 재검증이면 회차를 올려 기존 내용 아래 추가하게 한다.

## 2. 메인 세션 재검증

verifier 결과를 그대로 보고하지 않는다. 아래에 해당하는 항목을 골라 직접 재현하고 `VERIFY.md` "메인 세션 재검증"에 적는다.

- `일치` 판정 중 수치·조건·예외·에러 코드가 걸린 REQ: 해당 `파일:줄`을 직접 열어 조건을 하나씩 대조한다.
- "계획 밖 변경 없음" 같은 단정: `git diff --stat <통합 브랜치>...HEAD`와 `PLAN.md` 변경 파일 표를 직접 대조한다.
- 빌드 통과 주장: 명령을 다시 실행한다.

재현 결과가 하나라도 다르면 나머지 `일치` 항목도 모두 다시 확인하고, 차이를 `VERIFY.md`에 갱신한다.

## 3. 결과 처리

- `수정 필요`: 사용자에게 보고하고 `implement`로 돌아가 고친다. 고친 뒤 같은 REQ에 걸린 항목 전체를 다시 검증한다.
- `사람 승인 필요`: 근거와 추천안을 보여주고 답을 받는다.
- PRD 문제: `HANDOFF.md` "PRD 변경 요청".
- 보고에는 `확인 못한 부분`을 `일치`와 같은 비중으로 생략 없이 넣는다.
- 모두 정리되면 `HANDOFF.md` 다음 행동을 `api-verify`로 갱신한다(이 feature에 API가 없으면 `test-write`).

## Claude 대행

Codex를 쓸 수 없어 사용자가 Claude에게 대행을 요청한 경우(`docs/rules/workflow.md` "대행 작업").

- `verifier` 대신 `code-verifier` 에이전트를 `mode=code`로 실행한다. 메인 세션 재검증은 그대로 한다.
- 빌드·테스트·검사 스크립트는 실행해도 된다. 소스·테스트·`PLAN.md`는 고치지 않는다(훅이 차단).
- `수정 필요`가 나와도 `implement`·`test-write`로 돌아가지 않는다. `VERIFY.md`에 판정을 남기고, `HANDOFF.md` "대행 기록"의 "원래 담당이 할 일"에 수정 항목을 적은 뒤 멈춘다.
