# 문서-코드 정합성 검증

## 1. 검증 실행

- `verifier` 에이전트를 `mode=code`로 실행한다. 프롬프트에는 범위, feature ID, PRD 버전, 통합 브랜치, 산출물 경로(`artifacts/work/F-##/VERIFY.md`)만 준다. 구현 의도나 자기평가를 넣지 않는다.
- 범위: 첫 회차와 최종 회차는 `범위: 전체`. Claude가 구현 수정 요청을 반영한 뒤의 재검증은 `범위: 영향`으로 하고 직전 회차 번호와 반영된 요청 번호를 준다.
- 재검증이면 회차를 올려 기존 내용 아래 추가하게 한다.

## 2. 메인 세션 재검증

verifier 결과를 그대로 보고하지 않는다. 그 회차 범위 안에서 아래에 해당하는 항목을 골라 직접 재현하고 `VERIFY.md` "메인 세션 재검증"에 적는다.

- `일치` 판정 중 수치·조건·예외·에러 코드가 걸린 REQ: 해당 `파일:줄`을 직접 열어 조건을 하나씩 대조한다.
- "계획 밖 변경 없음" 같은 단정: `git diff --stat <통합 브랜치>...HEAD -- . ':!docs' ':!artifacts'`와 `PLAN.md` 변경 파일 표를 직접 대조한다(같은 브랜치의 문서·산출물 변경은 계획 대상이 아님).
- 빌드 통과 주장: 명령을 다시 실행한다.

재현 결과가 하나라도 다르면 나머지 `일치` 항목도 모두 다시 확인하고, 차이를 `VERIFY.md`에 갱신한다.

## 3. 결과 처리

- `수정 필요`: 사용자에게 보고하고 `HANDOFF.md` "구현 수정 요청"에 관련 REQ·PRD, 기대값(문서 원문), 실제값(코드 원문), 의심 지점(`파일:줄`)을 적은 뒤 멈춘다(수정은 Claude `implement`). Claude가 반영하면 `범위: 영향`으로 같은 REQ에 걸린 항목 전체를 다시 검증한다.
- `사람 승인 필요`: 근거와 추천안을 보여주고 답을 받는다.
- PRD 문제: `HANDOFF.md` "PRD 변경 요청".
- 보고에는 `확인 못한 부분`을 `일치`와 같은 비중으로 생략 없이 넣는다.
- 영향 회차가 `영향 범위 통과`이면 최종 전체 검증(`범위: 전체`)을 1회 한다. 첫 회차(전체)에 `수정 필요`가 없었고 그 뒤 소스가 바뀌지 않았으면 그 회차가 최종 전체 검증이다. 최종 전체 검증에서 `수정 필요`가 나오면 위 처리대로 하고 영향 재검증을 거쳐 다시 최종 전체 검증을 한다.
- 다음 단계로 넘어가는 조건: 마지막 전체 회차에 `수정 필요`가 없고, 그 회차의 기준 커밋·작업 트리 이후 소스가 바뀌지 않음. 충족하면 `HANDOFF.md` 다음 행동을 `api-verify`로 갱신한다(이 feature에 API가 없으면 `test-write`).

## Claude 대행

Codex를 쓸 수 없어 사용자가 Claude에게 대행을 요청한 경우(`docs/rules/workflow.md` "대행 작업").

- `verifier` 대신 `code-verifier` 에이전트를 `mode=code`로 실행한다. 메인 세션 재검증은 그대로 한다.
- 빌드·테스트·검사 스크립트는 실행해도 된다. 검증 중에는 소스·`PLAN.md`를 고치지 않고, 테스트는 고칠 수 없다(훅이 차단).
- `수정 필요`가 나와도 테스트는 고치지 않는다. `VERIFY.md`에 판정을 남기고, 소스 결함은 "구현 수정 요청"(Claude `implement`로 처리), 테스트 결함은 "대행 기록"의 "원래 담당이 할 일"에 적은 뒤 멈춘다.
