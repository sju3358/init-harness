# 개발계획

계획은 Claude가 쓰고 Claude가 계획대로 구현한다. Codex는 계획의 TC로 테스트를 쓰고 검증한다. Codex는 `PLAN.md`를 편집하지 않는다(훅이 차단).

## 1. 준비

- 현재 브랜치가 `feat|fix/ITD-####`인지 확인한다. 아니면 `work-start`부터.
- `sh .harness/hooks/prd-check.sh`가 `PRD 승인 유효`를 출력해야 한다. 실패하면 출력 원문을 전하고 멈춘다(`prd-verify`·`PRD 승인` 필요).
- `artifacts/work/F-##/`가 없으면 `cp -R artifacts/work/_template artifacts/work/F-##`로 만들고 각 파일의 `F-##`, 브랜치, PRD 버전을 채운다.
- 재계획이면 `HANDOFF.md`의 "계획 변경 요청"·"PRD 변경 요청" 중 처리가 `대기`인 항목을 모은다. 계획 승인 기록이 남아 있으면 사용자에게 `승인 취소`를 먼저 입력하게 한다(고치는 동안 소스 편집이 열려 있지 않게).

## 2. 작성

입력:

- `docs/prd/features/F-##.md`, `docs/prd/01-skillset.md`, `docs/prd/02-common.md`, `docs/prd/90-deploy-ops.md`
- `docs/api/README.md`와 이 feature의 엔드포인트(`- feature: F-##`)
- `docs/project.md`(스택, 디렉터리, 검증 명령)
- 현재 코드(`src/`). 재사용할 기존 클래스·유틸·패턴을 먼저 찾는다.

절차:

1. feature 명세의 모든 REQ를 "요구사항 매핑" 표에 옮기고 구현 방법과 변경 파일을 적는다. 이 feature의 엔드포인트는 모두 API 열에 적고, 컨트롤러·DTO·에러 코드를 문서의 필드 정의대로 만드는 계획을 쓴다.
2. 변경 파일 표에 신규/수정 구분과 이유를 적는다. 기존 코드를 재사용하면 그 `파일:줄`을 적는다.
3. 인수 조건마다 테스트 케이스(`TC-F##-##`)를 하나 이상 만든다. 정상·경계·예외를 구분하고 입력·상태와 기대 결과를 구체 값으로 적는다. 외부 시스템(메시지 큐, 외부 API)의 테스트 방식(Testcontainers, 목 서버 등)도 정한다.
4. 명세가 침묵하거나 모호한 부분은 추측으로 채우지 않는다. 코드·문서를 다시 읽어 해소할 수 있으면 `실측 가능`으로 적고 해소한다. 사람이 정해야 하면 `사람 승인 필요`로 적는다. PRD 자체의 누락·모순이면 계획을 멈추고 `prd-change`로 처리한다.
5. `01-skillset.md`에 없는 라이브러리, 신규 최상위 패키지·디렉터리, DB 스키마 변경은 반드시 `사람 승인 필요`로 올린다.
6. 재계획이면 반영한 요청을 "계획 변경 이력"에 적고 `HANDOFF.md`의 처리 칸을 `반영(PLAN 계획 변경 이력)` 또는 `반려(사유)`로 바꾼다.

## 3. 확인

- `sh scripts/check-trace.sh feature F-##`를 실행한다. 이 시점에는 테스트 관련 항목(`테스트 미연결`, `TC 미구현`)만 실패해야 정상이다. `계획 미반영`·`범위 밖`·`TC 없음`이 있으면 고친다.
- 인수 조건마다 TC가 있는지, TC의 기대 결과가 구체 값인지 본다.
- 변경 파일 표의 "재사용" 근거 `파일:줄`이 실제로 존재하는지 직접 열어 본다.

## 4. 확인 필요 항목

- `사람 승인 필요` 항목마다 근거(요구사항·PRD·현재 코드가 각각 무엇을 말하는지)와 추천안을 먼저 보여주고 `AskUserQuestion`으로 답을 받는다. 답변란은 사용자 답으로만 채운다.

## 5. 계획 승인

- 승인 요청 전에 요약한다: REQ 수, 변경 파일 수(신규/수정), TC 수, 신규 라이브러리·스키마 변경 여부, 남은 위험. 재계획이면 바뀐 부분.
- `PLAN.md` 상태를 `승인 대기`로 두고, 사용자에게 `계획 승인`을 한 줄로 입력하도록 안내한다. 다른 표현은 승인으로 보지 않는다.
- 승인 기록 메시지를 확인한 뒤 `PLAN.md` 상태를 `승인됨`으로 바꾸고 `HANDOFF.md`를 갱신한다: 담당 Claude, 단계 C5, 다음 행동 `implement`.
- 재계획이 아니면 같은 세션에서 `implement`로 이어 간다. Codex "계획 변경 요청"을 반영한 재계획이면 다음 행동을 `Codex test-write`로 적고 Codex 세션에서 이어 가도록 안내한다.
