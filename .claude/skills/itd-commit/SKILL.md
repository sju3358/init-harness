# ITD 커밋

규칙 원문은 `docs/rules/git.md`다. 커밋·push는 Claude가 한다. 미검증 경고·ITD 메시지·승인 확인을 이 스킬 한 곳에서 처리하기 위함이다.

## 1. 확인

- 현재 브랜치가 `feat|fix/ITD-####`인지 확인한다. 보호 브랜치면 멈춘다.
- `git status`로 커밋 대상을 확인한다. 이번 feature와 무관한 변경, 비밀값(.env, 키 파일)이 있으면 제외하고 알린다.

## 1-1. 미검증 경고 (구현이 포함된 커밋이면 반드시 1회)

테스트·검증(Codex)이 끝나지 않았다고 커밋을 막지는 않는다. 대신 커밋 전에 한 번 경고하고 사용자가 정한다.

- `artifacts/work/F-##/`에서 아래를 확인한다.

| 항목 | 완료로 보는 조건 |
| --- | --- |
| 문서-코드 검증 | `VERIFY.md`에 회차가 있고 결론에 `수정 필요`가 남지 않음 |
| API 검증 | `API-VERIFY.md`에 회차가 있고 불일치가 남지 않음 (이 feature에 API가 없으면 해당 없음) |
| 테스트 | `test-status.md`의 모든 TC가 `PASS`(실제 실행 기록 있음), `TEST-REPORT.md` 유효성 판정에 `약함`·`무효` 없음 |
| 전체 회귀 | `test-status.md` "마지막 전체 회귀"가 실패 0건이고, 그 실행 커밋 이후 소스·테스트가 바뀌지 않음. 미충족이면 feature는 완료가 아니므로 커밋 본문 `- 미검증: 전체 회귀`로 남기고, `00-overview.md` feature 상태를 `구현 완료`로 바꾸지 않음 |
| 명세 누락 | `TEST-REPORT.md` "명세 누락"의 항목이 `HANDOFF.md` "PRD 변경 요청"에서 처리됨 |
| 수정 요청 | `HANDOFF.md` "구현 수정 요청"·"PRD 변경 요청"에 `대기` 없음 |
| 최신성 | 각 검증 이후 소스가 다시 바뀌지 않음(`git log`·`git diff`로 검증 시점 이후 변경 확인) |

- 하나라도 충족하지 않으면, 미충족 항목과 근거(파일·회차)를 그대로 보여주고 `AskUserQuestion`으로 묻는다: "미검증 상태로 커밋" / "멈추고 Codex 검증부터". 숨기거나 축약하지 않는다.
- 사용자가 미검증 커밋을 고르면 커밋 본문 마지막에 `- 미검증: <항목>`을 한 줄 적고 진행한다. 같은 커밋 요청에서 경고를 반복하지 않는다.
- 모두 충족하면 경고 없이 진행한다.

## 2. 메시지

```
{종류}/ITD-#### {티켓 제목}

- 의미 단위 작업 내용
```

- 종류·티켓 번호는 브랜치명에서 가져온다(`ITD-1234-5678-9012`처럼 여러 묶음이면 그대로). 티켓 제목은 사용자에게 묻고 그대로 쓴다(접두어 추가·삭제 금지).
- `feat`: staged diff 근거로 3~7개 bullet. 파일 나열이 아니라 무엇을 왜 했는지.
- `fix`: `- 원인:`, `- 해결:` 두 줄.
- `artifacts/` 산출물, 포맷터 자동 수정, lockfile은 본문에서 뺀다.
- 커밋은 쌓아도 된다. 이미 push한 커밋은 amend하지 않는다.

## 3. 승인과 실행

- 커밋 대상 파일 목록과 메시지 미리보기를 보여주고, `커밋 승인`(push까지면 `커밋 푸시 승인`)을 한 줄로 입력하도록 안내한다.
- 승인 기록 메시지를 확인한 뒤 실행한다. 메시지는 heredoc으로 넘긴다.

```bash
git add <파일들>
git commit -F - <<'EOF'
feat/ITD-1234 제목

- 내용
EOF
```

- push는 `푸시 승인` 기록이 있을 때만 `git push -u origin HEAD`로 현재 브랜치만 올린다. PR은 만들지 않는다.
- 훅에 막히면(형식 위반, 승인 만료) 우회하지 않고 메시지를 그대로 전하고 다시 승인을 요청한다.

## 4. 보고

커밋 해시, 제목, push 여부와 원격 브랜치를 보고한다. `HANDOFF.md` 상태를 갱신한다. PR·병합과 병합 후 브랜치 정리는 사용자가 직접 한다고 덧붙인다.
