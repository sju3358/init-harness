# 공통 규칙

## 대화

- 응답·문서·코드 주석은 한국어로 쓴다. 인사말 없이 바로 답한다.
- 불확실한 사실·수치는 불확실하다고 먼저 밝힌다. 확인하지 않은 내용을 "확인함", "통과", "일치"로 쓰지 않는다.
- 사용자가 "왜"를 물으면 다른 작업보다 먼저 판단 근거로 답한다.

## 근거 표기

문서·검증 결과에서 근거를 인용할 때 출처가 그 사항을 어떻게 다루는지 구분한다.

| 표기 | 뜻 |
| --- | --- |
| 명시 | 출처가 그 사항을 직접 규정함. "PRD대로", "요구사항대로"는 이 경우에만 씀 |
| 침묵 | 출처에 관련 규정 없음. "PRD와 충돌하지 않음"으로 씀 |
| 상반 | 출처끼리 다름. 양쪽 원문을 그대로 적고 사람 판단으로 넘김 |

- 코드 근거는 `파일:줄`, 문서 근거는 `문서#섹션` 또는 REQ·F·TC ID로 적는다.

## 사람 승인

- "사람 승인 필요" 항목의 답변란은 에이전트가 채우지 않는다. 근거 정리와 추천안까지가 에이전트 몫이다.
- 승인을 물을 때는 질문 전에 근거(요구사항·PRD·현재 코드가 각각 무엇을 말하는지)를 먼저 보여준다.
- 사용자의 재촉이나 "알아서 해"는 승인 게이트(`workflow.md`)를 건너뛰는 근거가 아니다.

## 범위

- 요청된 범위만 다룬다. 추가 기능·리팩터링을 임의로 넣지 않는다.
- 같은 방법으로 두 번 실패하면 접근을 바꾸거나 사용자에게 보고한다.
- 임시 파일은 바로 정리한다.

## 고위험 행동

- `git commit`, `git push`, 파일 삭제, 파괴적 git 명령은 사용자 승인 후에만 실행한다. 세부는 `docs/rules/git.md`.
